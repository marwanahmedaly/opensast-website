Run an independent CI scan

CI scanning requires no dashboard account or worker token and does not publish to dashboard scan history. Run from the target Git repository root, with the trusted scanner installed outside that checkout. Put state and reports outside the scanned directory.

opensast ci \
  --project-key my-team/my-project \
  --state "$HOME/.local/share/opensast/ci" \
  --output /tmp/opensast-my-project/report.json \
  --base origin/main \
  --model-revision IMMUTABLE_WEIGHT_REVISION

This example uses saved engine settings. Without guided setup, also provide --codeql, --query-search-path, --endpoint and --model, and an allowed host for non-loopback inference. CI requires a pinned model revision.

Understand the comparison

Fetch the base reference and enough history. --base origin/main compares its merge-base with HEAD against the current working tree. The first comparison needs two scans; subsequent matching base/head snapshots can reuse their own caches. Changed snapshots still receive whole-repository CodeQL analysis.

Without --base, this is a branch scan with all current positive alerts considered by the gate. --full bypasses reuse. Git baseline comparison rejects submodules rather than silently excluding their source.

Configure GitHub Actions

  1. Provision an isolated company self-hosted Linux runner with trusted OpenSAST, CodeQL packs and internal inference.
  2. Copy the workflow example shown on this website into the target repository’s .github/workflows/opensast.yml.
  3. Set runner labels, trusted executable paths, private state/output locations, endpoint, served model and immutable weight digest.
  4. Configure private action repository access and review the scanner/action revision before enabling the workflow.
  5. Keep complete Git history and allow only approved internal contributors on the runner.
The supplied template pins the historically reviewed 0.1.0 action commit. It is not a published/tested 0.2.0 installer workflow. The 0.2.0 wheel now bundles scanner assets; validate your chosen scanner/action pairing before deployment.

Do not install or run the scanned PR as the trusted scanner. The template excludes fork PRs and uses repository read permission. Source, evidence and caches remain on the runner; GitHub receives workflow/check status. The integration does not upload SARIF, post PR comments or send reports to the dashboard.

Interpret reports and exit codes

Field / statusMeaning
new_alert_idsPositive decisions without a matching positive baseline alert.
existing_alert_idsPositive decisions matched to baseline alerts.
no_longer_reported_alert_idsBaseline positives absent from current positives; this is not proof of a fix.
Exit 0Completed passing scan.
Exit 1Execution failure or alert gate failed.
Exit 2Incomplete verification in either comparison revision.

--fail-on none disables the alert gate but still fails incomplete verification. Matching maps unchanged lines; renamed files or modified operation lines can conservatively create extra new alerts. Review them.

summary.changed_files compares with the previous cache snapshot; git.changed_files compares with the PR base. They can differ on repeated runs. Full reports retain all findings, evidence, timings and cache accounting. Read the full CI reference on this website.
