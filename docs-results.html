Results and human review

Understand model verdicts, evidence, review states and JSON exports.

New to OpenSAST? Follow the seven-step first scan guide. These pages explain the details when you need them.

Read the model decision

VerdictMeaning and next action
VULNERABLEThe verifier identifies a suspected vulnerability from the collected evidence. Inspect the code, reachability and defenses before confirming it.
NOT_VULNERABLEThe verifier judges this candidate safe in the supplied context. This is not a security guarantee for the whole project.
UNRESOLVEDNo final vulnerability judgment is available. Review missing evidence/configuration; suspect-only scans also produce unresolved suspects.
SYSTEM_ERRORVerification could not complete reliably. Inspect service/worker logs, correct the failure and rescan.

The dashboard offers a Filter verdict control. A context-expansion request is an intermediate workflow step, not proof of safety. Do not treat unknown decisions or execution errors as negative findings.

Review the code and its conditions

  1. Open a finding and locate its CWE, rule and referenced file/line.
  2. Follow evidence about the input origin, assignment, callers and sensitive operation.
  3. Check whether input is attacker-controlled in the relevant configuration.
  4. Inspect validation, escaping, parameterization or other defenses at the operation.
  5. Record your conclusion and the reason in the human review state.

Evidence packets contain focused excerpts and relationships, not the entire repository. A related call can be possible rather than proven. Missing input origins, callers or configuration can leave the decision uncertain; inspect the source when necessary.

Record human review separately

opensast findings JOB_ID
opensast review JOB_ID FINDING_ID confirmed --note "Verified input reaches the operation without the required defense"
opensast review JOB_ID FINDING_ID dismissed --note "Reviewed: this value is not attacker-controlled"
opensast review JOB_ID FINDING_ID open --note "Needs further investigation"

Use open, confirmed or dismissed in the dashboard or CLI. A human review state is separate from the saved model verdict. Changing review state does not rewrite the model response. Members and administrators can review; viewers can read and export.

Export and interpret counts

opensast export JOB_ID --output /private/reports/opensast-scan.json

The dashboard's Export JSON downloads the scan result. It includes findings and their saved evidence/decisions. Protect exports as source-bearing confidential material.

A candidate is a static suspect; a model alert has a VULNERABLE verdict; a confirmed finding has a human review decision. These counts are different. Repeated findings can concern the same underlying vulnerability. A candidate disappearing or an alert no longer being reported does not by itself prove a fix.

Your project cannot have trustworthy recall, precision or F1 merely from its scan output. Those metrics require independently reviewed ground truth, including missed vulnerabilities. The research evaluation keeps labeled cases and reviewed alert counts separate.

Scan command exit status

CommandStatus
scan --wait0: completed verification; 1: failed/cancelled job; 2: incomplete configured verification. Positive findings do not themselves fail this interactive command.
ci0: completed passing gate; 1: execution failure or alert gate failed; 2: incomplete verification. CI has a separate configurable alert gate.
