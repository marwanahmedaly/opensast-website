Deployment and maintenance

Headless access, company hosting, private storage, backups and service operation.

New to OpenSAST? Follow the seven-step first scan guide. These pages explain the details when you need them.

Access a headless machine

Guided setup binds the dashboard and local model to loopback. Forward the dashboard over SSH:

ssh -L 8765:127.0.0.1:8765 USER@HOST

Then open http://127.0.0.1:8765 on your own computer. Register projects on the machine holding their source using opensast init --no-browser. This documentation site is separate from the authenticated dashboard.

Expose an internal company dashboard

opensast serve --host 127.0.0.1 --port 8765 \
  --public-url https://opensast.company.internal

Put an internal HTTPS reverse proxy in front of this backend. Preserve the exact browser host/origin, serve it at the root URL, and use your company certificate and network access controls. Use the same data location for account bootstrap and serving. A non-loopback deployment requires an HTTPS public origin.

--trusted-origin adds an exact accepted HTTPS origin, or a private Tailscale HTTP IP origin for development. It does not open a port, bind an interface or establish forwarding. Unexpected Host/Origin values are intentionally rejected.

The prototype does not provide SSO, MFA, high availability or enterprise certification. Use dedicated non-root trusted workers; the backend trusts their reported results. Keep inference and source-bearing storage within your infrastructure.

Start and stop services

opensast doctor
opensast start
opensast stop
opensast restart

These commands manage recorded user-local services and remembered workers; they do not manage independently launched processes. Stopping preserves data. They are not a boot-time supervisor: run opensast start after reboot or configure your organization’s supervisor.

Locate and back up data

Default pathContents
~/.local/share/opensast-appApplication environments, current/previous links. Separate from user data.
~/.local/share/opensast or OPENSAST_HOMEProduct data root.
server/opensast.sqlite3Accounts, workspaces, scan results, session hashes and audit records.
client/credentials.jsonPrivate CLI login token.
workers/PROJECT_ID/Worker credential, baseline and runs/JOB_ID source/evidence/logs.
installation.jsonSaved engine settings.
logs/ and services/Installation logs, managed service logs and process records.

Back up the backend using a SQLite-consistent backup procedure, or stop backend writes and preserve the database with any WAL/SHM files consistently. Back up worker baselines/runs separately if you need evidence and reuse state. Application reinstall alone is not a data backup.

Reports and run logs can contain source code, prompts and model responses. Keep them private. Automatic retention/pruning is not implemented; budget disk capacity and apply an external retention policy. Restoring only the backend does not restore a worker’s local baseline.
