Installation

Requirements, guided setup, offline installation and updates.

New to OpenSAST? Follow the seven-step first scan guide. These pages explain the details when you need them.

Step 1 — Check requirements

Automatic provisioning targets Linux x86-64, Python 3.11.8+ or 3.12+, Python venv, and flock. Online source installation also needs Git, repository access and a Python package index. The installer uses your account and does not install system packages with sudo.

CodeQL use is governed by its license terms; installing OpenSAST does not grant additional rights for proprietary analysis. Confirm applicable authorization for your deployment.

Allow at least 256 MiB for the application bootstrap and 2 GiB free for CodeQL provisioning, plus space for dependencies, extracted packs, models and scan snapshots. The optional default Qwen GGUF is about 17.4 GB. Its 24 GiB RAM/GPU-memory check is a provisioning heuristic; CPU inference can be slow.

Default engine pins: CodeQL 2.27.1, Python queries 1.8.11, Python libraries 7.2.6, and llama.cpp b11070. Upstream Ubuntu CPU/CUDA binaries may need a compatible system library or GPU driver; you can supply your own compatible llama-server.

Step 2 — Install and choose inference

bash scripts/install.sh
  1. Review reported RAM, GPU memory and free disk.
  2. Install the pinned CodeQL tools or point setup at your existing tools.
  3. Choose the pinned Qwen GGUF download, an existing local GGUF, or a company-internal llama.cpp endpoint.
  4. Choose an administrator username, workspace and private password.
  5. Wait for service readiness checks, then open the dashboard.

The default model is Qwen3-Coder-30B-A3B-Instruct Q4_0. Setup uses one 16,384-token slot and a 400-token completion budget. These provisioning settings do not reproduce every historical evaluation's concurrency.

The installer and source are publicly available at the OpenSAST repository. For one-command setup, run curl -fsSL https://raw.githubusercontent.com/marwanahmedaly/opensast/main/scripts/install.sh | bash. Inspect the script first if you prefer. For installation from a wheel or alternate checkout:

bash scripts/install.sh --source /path/to/opensast-checkout
# Or use a prepared wheel:
bash scripts/install.sh --wheel /path/to/evidence_grounded_aisast-0.2.0-py3-none-any.whl

Open a new terminal if ~/.local/bin was added to PATH. Read the complete installation reference on this website for distribution and unattended setup details.

Install inside an offline network

Prepare the installer, wheel and dependency wheelhouse on a connected build machine. Transfer the pinned CodeQL tools/packs, GGUF and compatible llama-server into the internal network. The application wheel contains scanner assets, not tool binaries or model weights.

bash install.sh --offline \
  --wheel /internal/packages/evidence_grounded_aisast-0.2.0-py3-none-any.whl \
  --wheelhouse /internal/packages/wheelhouse -- \
  --codeql /internal/codeql/codeql \
  --query-search-path /internal/codeql-packs \
  --gguf /internal/models/qwen.gguf \
  --llama-server /internal/llama/llama-server \
  --backend cpu

Offline setup reports missing assets rather than fetching them. HTTPS mirrors can be configured through OPENSAST_DOWNLOAD_MIRROR; checksums remain pinned. Use OPENSAST_REPOSITORY for an internal source mirror. Do not embed credentials in URLs.

Update, restart and retain data

Back up product data first. Run the installer from the chosen updated source checkout, then:

opensast restart
opensast doctor

The installer creates a new isolated environment and promotes it after package installation succeeds. Previous environments remain available; application data, accounts and scan history are separate. Running processes use their original environment until restarted. Reconfigure engine choices with opensast setup --reconfigure.

The new installer has been built and source-reviewed. Fresh-machine, offline and upgrade acceptance runs remain pending; earlier product and CI tests do not validate these new provisioning paths.
