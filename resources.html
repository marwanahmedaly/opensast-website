04 / QUESTIONS

Before you run a scan.

Practical boundaries of the current research prototype.

Does OpenSAST cover every OWASP Top 10 category?

No. This research targets CWE-22, CWE-78, CWE-79 and CWE-89 within declared native Python and selected framework patterns.

Does code leave my infrastructure?

The scanner and model can run locally or inside your company network. Provision the inference endpoint internally and enforce your own network egress policy. This research site contains public-facing summaries, not a scan upload service.

Are later scans limited to edited files?

Unchanged scans can be skipped and eligible verifier decisions reused. On changed scans, CodeQL still analyzes the full snapshot and context is gathered fresh to preserve cross-file relationships.

How much hardware and time are required?

Requirements depend on the model, quantization and repository. The reported Qwen experiments used a local 30B model. No universal minimum or two-hour full-scan guarantee is established; the 7-project repository evaluation had a 24h 25m 40s calendar interval including interruption and recovery. See the evaluation page for separate runtime boundaries.

Is a model verdict a confirmed vulnerability?

No. VULNERABLE is the model's decision after pipeline validation. A reviewer should inspect the code and conditions; unresolved outputs and system errors are reported separately.

Can I reproduce every historical result from these downloads?

No. The downloads provide the thesis, selected evidence and metrics. Complete reproduction also requires pinned repositories, matching query and schema source, model weights, environments and original evaluation ledgers. A digest alone cannot reconstruct missing bytes.
