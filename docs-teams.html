Accounts and workspaces

Separate team access, invite users, and manage credentials.

New to OpenSAST? Follow the seven-step first scan guide. These pages explain the details when you need them.

On this pageChoose a workspace boundaryCreate a workspace and add membersSign in and change your passwordRotate a project worker credential

Choose a workspace boundary

RoleAccess
AdministratorManage workspace membership, projects and worker credentials; scan, cancel, review, read and export.
MemberScan, cancel, review, read and export accessible workspace projects.
ViewerRead projects/findings and export; cannot scan or change reviews.

Membership grants access to the workspace’s projects. There is no separate per-project membership boundary. Create separate workspaces for teams that must not see one another’s projects. The last administrator cannot be removed or demoted.

Create a workspace and add members

opensast workspace create "Security team"
opensast workspace list
opensast members WORKSPACE_ID
opensast members WORKSPACE_ID --username alice --role member --new-user
opensast members WORKSPACE_ID --username alice --role viewer
opensast members WORKSPACE_ID --username alice --role remove
opensast audit WORKSPACE_ID

Replace WORKSPACE_ID with the actual ID from the list. New-user creation prompts for an initial password. Add an existing user without --new-user; this does not replace their password. Dashboard controls include New workspace, Members and Audit log.

Sign in and change your password

opensast login --username alice --server https://opensast.company.internal
opensast password
opensast logout

The CLI remembers the server and keeps its session token in private local storage. The dashboard uses a separate browser session. Changing a password revokes all that user’s sessions, so sign in again. No shared default account/password is shipped.

Rotate a project worker credential

Worker credentials allow a registered machine to claim and report that project’s jobs. They are separate from user login credentials.

cd /path/to/registered-project
opensast worker-token
# On a worker machine receiving an administrator-provided credential:
opensast worker-token --import

Rotation immediately revokes the previous token. Import the new credential privately and restart the corresponding worker. Do not put credentials in Git, screenshots or issue reports. Managed workers can be restarted using opensast restart.
