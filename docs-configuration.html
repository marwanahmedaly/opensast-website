Inference and configuration

Use local weights or an internal endpoint, and manage saved engine settings.

New to OpenSAST? Follow the seven-step first scan guide. These pages explain the details when you need them.

Set up the analysis engines

Guided setup stores defaults in OPENSAST_HOME/installation.json. Explicit worker/CI flags override saved defaults. To use already provisioned CodeQL and an internal inference server:

opensast setup --reconfigure \
  --codeql /opt/codeql/codeql \
  --query-search-path /opt/codeql-packs \
  --endpoint https://inference.company.internal/v1 \
  --allow-model-host inference.company.internal \
  --model YOUR_SERVED_MODEL \
  --model-revision IMMUTABLE_WEIGHT_REVISION

Use the served model name and an immutable weight revision/digest. The operator must ensure that an allowed host is within the company network. The allowlist is not a network firewall.

Check endpoint compatibility

The current integration needs llama.cpp-compatible /v1/models, chat completions, /apply-template and /tokenize. A generic chat-only API is insufficient. The template/tokenizer endpoints support accurate packet budgeting.

Local inference normally listens at http://127.0.0.1:8000/v1. Setup accepts local GGUF weights through --gguf and a compatible executable through --llama-server; choose --backend cpu or cuda. CPU speed and GPU compatibility vary.

Context and output budgets

--context-window sets the usable model window; --max-tokens reserves completion space. The configured window must match actual serving capacity. Larger context can include more evidence but uses more memory and time; it cannot restore facts the collector never found.

The packaged defaults are 16,384 context tokens and 400 completion tokens. Changing the model, prompts, serving settings or budgets does not inherit the thesis measurements. Use opensast doctor to check readiness; it does not assess detection quality.

Run discovery without verification

opensast worker --suspect-only

This explicitly omits verification, including a saved model configuration. Findings remain unresolved static suspects. Use it to inspect discovery coverage; do not compare its suspect count with confirmed vulnerabilities.

Useful setup controls

--dashboard-port and --model-port select separate unprivileged ports; defaults are 8765 and 8000. --no-start provisions without launching services. For unattended first setup use --non-interactive --yes, explicit engine choices and --password-file /private/initial-password. Protect that file; a password is not supplied as a command-line value.

Set OPENSAST_HOME consistently for all processes when changing data storage. Application environments use a separate installer prefix. Read storage and backups before moving data.
